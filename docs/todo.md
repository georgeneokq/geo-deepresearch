## Planned Improvements

- The condition for reading a whole internal document is that at least 2 chunks from a certain file must have a score of above 0.4. This is ok for small documents, say less than 10 pages, but if there was a document with more than 100 pages this criteria is too lax. The plan for improvement is to dynamically increase the minimum number of high scoring chunks to reduce time taken to potentially process many redundant parts in a document.
- Currently using Docling for extracting tables, which seem to work well, but tables that span multiple pages are broken in which the table continuation in the next page may have missing columns, and merged cells aren't duplicated into each row/column. The plan for improvement is to find another tool, or find a way to postprocess the extracted tables if they are broken (but this is not a trivial task). Another idea is to use a lightweight VLM (Vision Language Model) to understand complex table structure and output into markdown tables.
- As this project is focused on enhancing the threat hunting process, I have only created a CTI (Cyber Threat Intelligence) specialist agent, and a "General" agent as a fallback for all other queries, but I would like to also create a "live asset price" agent which shows that this framework is easily extensible to create new specialized agents
- Currently, the specialists are "specializing" in their field by providing a predefined list of sources that will definitely be browsed before moving on to let the LLM do "free browsing", but for financial data, instead of searching the general internet, it could do better with a dedicated tool to access Yahoo Finance API. This would require allowing the agent subclass to be able to add custom tools and add new instructions to the underlying LLM calls, but that would break the simplicity of implementation that comes with the current approach. But this seems to be a tradeoff that is worthwhile, and can simply be provided as an option to override the usable tools and system prompts only when necessary.
- I should probably include instructions to the LLMs to be strict in evaluating the source's credibility and whether it is considered outdated to be used as a source.
- Currently no handling of images, which could lead to a significant loss of information. Due to lack of time, I am not sure whether I can implement it by the date of presentation, but my plan is to incorporate a lightweight VLM that can convert images to text.
- E2E Testing can be improved by asserting that the number of IOCs retrieved must be at least 95% of the actual number of IOCs that is known on the internet. As I am facing a challenge in finding out why my research agent hardly manages to extract 100% of the available IOCs even though they are returned in the search results, I would currently set the threshold to be 95% until I catch the root of the problem and attain perfection.
